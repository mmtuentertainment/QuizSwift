# Phase 2.1: Intelligent Question Curation - Research

**Researched:** 2026-01-24
**Domain:** Pedagogical AI Prompting, Multi-Pass Reasoning, Math Canvas Interfaces
**Confidence:** MEDIUM-HIGH

## Summary

This research investigates how to transform the current chunk-by-chunk extraction approach into an intelligent question curation system that reads full documents, reasons pedagogically, and generates high-quality comprehension questions. The new system will generate 2x the requested question count, allowing teachers to curate the final set.

The key findings are:
1. **Multi-pass reasoning should use separate API calls**, not one long prompt - this provides better control, allows model switching, and fits within Qwen3:8b's 32K native context
2. **Bloom's Taxonomy prompting is well-established** - LLMs achieve ~78% high-quality questions with proper prompting, though higher-order questions (Analyze/Evaluate/Create) require more sophisticated techniques
3. **Full document context is feasible** with Qwen3:8b at 32K tokens (~24K words), but requires careful num_ctx configuration and VRAM management
4. **Show-your-work math** is best served by tldraw or Excalidraw for drawing + KaTeX for equation rendering
5. **Self-evaluation prompting** (Reflexion pattern) can improve question quality through iterative refinement

**Primary recommendation:** Implement 5 sequential reasoning passes using Vercel AI SDK's multi-step capabilities, with each pass having a focused prompt. Use tldraw for canvas drawing with KaTeX overlays for math equation rendering.

## Multi-Pass Reasoning Architecture

### Why Separate API Calls vs. One Long Prompt

| Approach | Pros | Cons | Verdict |
|----------|------|------|---------|
| Single long prompt | Fewer API calls, full context in one shot | Hits context limits, less control, no intermediate inspection | Not recommended |
| Chained API calls | Controllable steps, intermediate results, can switch models | More calls, must manage state | **Recommended** |
| AI SDK multi-step | Built-in loop handling, prepareStep for control | Designed for tool loops, not reasoning passes | Partial fit |

**Recommendation:** Use sequential `generateText` calls with structured output, passing results forward as context.

### Five-Pass Architecture

```
Pass 1: Content Analysis
  Input: Full document text
  Output: { keyTopics: [], learningObjectives: [], contentType: "textbook|worksheet|article" }

Pass 2: Concept Extraction
  Input: Pass 1 output + document text
  Output: { concepts: [{ name, definition, importance: 1-5, dependencies: [] }] }

Pass 3: Question Generation (2x count)
  Input: Pass 1 + Pass 2 outputs + document text
  Output: { questions: [{ text, type, bloomLevel, targetConcept, answer, rationale }] }

Pass 4: Self-Evaluation & Ranking
  Input: Pass 3 questions + Pass 1/2 context
  Output: { evaluations: [{ questionId, qualityScore, comprehensionDepth, clarity, improvements }] }

Pass 5: Final Selection
  Input: All previous passes
  Output: { selectedQuestions: [...], rankings: [...], diversityScore }
```

### Context Management Strategy

**Qwen3:8b context limits:**
- Native context: 32,768 tokens
- Extended via YaRN: up to 131,072 tokens (but quality degrades)
- Ollama default num_ctx: 4,096 (MUST override)
- VRAM impact: ~1GB per 4K context increase

**Strategy for 8GB VRAM (RTX 2080):**
```
Document up to ~20K tokens (~15K words) can fit with:
- 20K tokens for document
- 4K tokens for pass outputs/context
- 8K tokens for generation buffer
= 32K total context

For larger documents:
- Summarize in Pass 1
- Use summary + key excerpts in subsequent passes
```

**Ollama configuration (Modelfile):**
```
FROM qwen3:8b
PARAMETER num_ctx 32768
PARAMETER temperature 0.7
```

**Warning:** Ollama silently truncates prompts exceeding num_ctx from the START, losing the question at the beginning. Always configure explicitly.

## Pedagogical Prompting Strategy

### Bloom's Taxonomy Integration

Bloom's Revised Taxonomy levels and question stems:

| Level | Cognitive Process | Question Stems | LLM Success Rate |
|-------|------------------|----------------|------------------|
| Remember | Recall facts | What is...? List... Define... | HIGH (~85%) |
| Understand | Explain meaning | Explain... Describe... Summarize... | HIGH (~80%) |
| Apply | Use in new situation | How would you...? Demonstrate... | MEDIUM (~70%) |
| Analyze | Break down components | Compare... Contrast... Why does...? | MEDIUM (~65%) |
| Evaluate | Make judgments | Justify... Assess... Which is better...? | LOW (~55%) |
| Create | Produce new work | Design... Compose... What if...? | LOW (~45%) |

**Source:** [Automated Educational Question Generation at Different Bloom's Skill Levels](https://arxiv.org/html/2408.04394v1)

### Prompting Strategy for Quality Questions

**Research finding:** Chain-of-Thought prompts with skill definitions and example questions (PS4) outperform simpler prompts. However, adding too much information (PS5) paradoxically reduces performance.

**Recommended prompt structure for Pass 3:**

```markdown
You are an expert educator creating comprehension questions. Your goal is to test
UNDERSTANDING, not memorization.

## Bloom's Taxonomy Levels to Target:
- **Understand (40%)**: Test if students grasp meaning and can explain concepts
- **Apply (30%)**: Test if students can use knowledge in new situations
- **Analyze (20%)**: Test if students can break down and compare concepts
- **Evaluate (10%)**: Test if students can make reasoned judgments

## Key Concepts to Test:
{pass2Concepts}

## Learning Objectives:
{pass1Objectives}

## What Makes a GOOD Comprehension Question:
- Tests understanding of WHY, not just WHAT
- Requires connecting multiple concepts
- Cannot be answered by keyword matching
- Has a defensible correct answer from the source

## What to AVOID:
- Trivial recall ("What color was the cat?")
- Questions answerable without reading the text
- Ambiguous questions with multiple valid answers
- Questions about irrelevant details

## Document Text:
{documentText}

Generate {count * 2} high-quality questions targeting the concepts above.
For each question, specify:
- The Bloom's level it targets
- Which concept it tests
- Why this tests comprehension (not just recall)
```

### Self-Evaluation Prompt (Pass 4)

Based on the [Reflexion pattern](https://www.promptingguide.ai/techniques/reflexion):

```markdown
You are evaluating the quality of generated questions. For each question, assess:

1. **Comprehension Depth** (1-5): Does this test understanding or just recall?
   - 1: Pure memorization (what, when, who)
   - 3: Basic comprehension (explain, describe)
   - 5: Deep understanding (analyze, evaluate, synthesize)

2. **Clarity** (1-5): Is the question unambiguous?
   - 1: Multiple interpretations possible
   - 5: Crystal clear what's being asked

3. **Answerability** (1-5): Can this be answered from the source?
   - 1: Requires external knowledge
   - 5: Fully answerable from document

4. **Difficulty Appropriateness** (1-5): Is this appropriate for the content level?
   - 1: Trivially easy or impossibly hard
   - 5: Appropriately challenging

5. **Improvements**: What specific changes would make this better?

For questions scoring below 3.5 average, suggest a rewrite.
```

### Question Type Distribution

For balanced assessment, target this distribution:

| Type | Percentage | When to Use |
|------|------------|-------------|
| Multiple Choice | 30% | Factual/conceptual understanding |
| Short Answer | 25% | Explain reasoning |
| Show Your Work | 20% | Math/process demonstration |

### React Implementation Sketch

```typescript
// Source: tldraw documentation patterns
import { Tldraw, useEditor } from 'tldraw';
import 'tldraw/tldraw.css';
import { InlineMath } from 'react-katex';
import 'katex/dist/katex.min.css';

function ShowYourWorkQuestion({ question, onSubmit }) {
  const [finalAnswer, setFinalAnswer] = useState('');
  const editorRef = useRef<TldrawEditor | null>(null);

  const handleSubmit = async () => {
    const editor = editorRef.current;
    if (!editor) return;

    // Get canvas state for saving
    const sceneData = editor.getSnapshot();

    // Render to PNG for easy review
    const imageBlob = await editor.toImage('png');

    onSubmit({
      canvasData: sceneData,
      canvasImage: imageBlob,
      finalAnswer,
    });
  };

  return (
    <div className="show-your-work">
      {/* Question with math rendering - using react-katex component (safe) */}
      <div className="question-text">
        <InlineMath math={question.latexContent} />
      </div>

      {/* Canvas */}
      <div className="canvas-container" style={{ height: 400 }}>
        <Tldraw
          onMount={(editor) => { editorRef.current = editor; }}
          components={{
            // Optionally hide some UI elements
            DebugPanel: null,
            DebugMenu: null,
          }}
        />
      </div>

      {/* Final answer with LaTeX preview */}
      <MathInput
        value={finalAnswer}
        onChange={setFinalAnswer}
        placeholder="Enter your final answer"
      />

      <button onClick={handleSubmit}>Submit Answer</button>
    </div>
  );
}
```

## Technical Constraints

### Ollama/Qwen3:8b Limits

| Constraint | Value | Impact |
|------------|-------|--------|
| Native context | 32,768 tokens | ~24K words of document |
| VRAM (RTX 2080) | 8GB | Must use Q4_K_M quantization |
| VRAM at 32K ctx | ~7-8GB | Leaves little headroom |
| Speed | ~40 tok/s | Each pass takes 10-30s |
| Extended context | 131K (YaRN) | Quality degrades significantly |

### Context Token Budget

```
For a typical 10-page PDF (~5000 words = ~6500 tokens):

Pass 1: 6500 (doc) + 500 (prompt) = 7000 input, ~500 output
Pass 2: 6500 (doc) + 500 (P1) + 500 (prompt) = 7500 input, ~1000 output
Pass 3: 6500 (doc) + 500 (P1) + 1000 (P2) + 1000 (prompt) = 9000 input, ~3000 output
Pass 4: 3000 (questions) + 500 (P1) + 1000 (P2) + 500 (prompt) = 5000 input, ~2000 output
Pass 5: 5000 (evaluated) + 500 (prompt) = 5500 input, ~500 output

Total: ~40K tokens processed across 5 passes
Time estimate: 5 passes x 20s average = ~100s total
```

### For Large Documents (>25K tokens)

When documents exceed comfortable context limits:

1. **Pass 0 (Summarization):** Create a 5000-token summary
2. **Hybrid approach:** Use summary for reasoning, full text for verification
3. **Section-based processing:** Divide by chapters/sections, process independently

```typescript
async function handleLargeDocument(documentText: string, tier: Tier) {
  const tokenCount = estimateTokens(documentText);

  if (tokenCount > 25000) {
    // Create summary first
    const summary = await generateText({
      model: getExtractionModel(tier),
      prompt: `Summarize this educational document in ~4000 words,
               preserving all key concepts, definitions, and testable facts:\n\n${documentText}`,
    });

    return {
      fullText: documentText,
      summary: summary.text,
      useSummaryForReasoning: true,
    };
  }

  return { fullText: documentText, useSummaryForReasoning: false };
}
```

## Common Pitfalls

### Pitfall 1: Ollama Context Truncation
**What goes wrong:** Questions generated ignore document content
**Why it happens:** num_ctx defaults to 4096, Ollama silently truncates from START
**How to avoid:** Always create custom Modelfile with `PARAMETER num_ctx 32768`
**Warning signs:** Generated questions seem generic or unrelated to document

### Pitfall 2: Higher-Order Questions Failing
**What goes wrong:** Most questions are basic recall despite Bloom's prompting
**Why it happens:** LLMs default to lower cognitive levels without strong guidance
**How to avoid:** Explicit distribution targets in prompt, examples of each level
**Warning signs:** >60% of questions are Remember/Understand level

### Pitfall 3: Context Loss Between Passes
**What goes wrong:** Later passes don't reference earlier insights
**Why it happens:** Not including previous pass outputs in subsequent prompts
**How to avoid:** Accumulate and include all pass results in context
**Warning signs:** Pass 3 questions don't align with Pass 1/2 identified concepts

### Pitfall 4: Canvas State Serialization
**What goes wrong:** Student work lost on page refresh
**Why it happens:** Canvas state not persisted to database
**How to avoid:** Auto-save canvas snapshots, store in StudentResponse.canvasData
**Warning signs:** Student complaints about lost work

### Pitfall 5: VRAM Exhaustion
**What goes wrong:** Ollama crashes or becomes extremely slow
**Why it happens:** 32K context on 8GB VRAM leaves no headroom
**How to avoid:** Monitor VRAM, fall back to smaller context for large docs
**Warning signs:** GPU memory errors, <5 tok/s speed

## Open Questions

### 1. Optimal Pass Count
- **What we know:** 5 passes provide clear separation of concerns
- **What's unclear:** Whether 3 passes (analyze + generate + evaluate) would suffice
- **Recommendation:** Start with 5, measure quality, consider consolidating

### 2. Question Deduplication
- **What we know:** Multi-pass generation may produce similar questions
- **What's unclear:** Best deduplication strategy (embedding similarity vs semantic)
- **Recommendation:** Use embedding similarity with 0.9 threshold in Pass 5

### 3. Teacher Override of AI Rankings
- **What we know:** Teachers select final questions from 2x pool
- **What's unclear:** How much AI ranking should influence default ordering
- **Recommendation:** Show AI rankings but allow full re-ordering

### 4. Canvas Grading Workflow
- **What we know:** Canvas drawings need review
- **What's unclear:** How to help teachers efficiently grade visual work
- **Recommendation:** Render canvas to PNG, show alongside final answer
